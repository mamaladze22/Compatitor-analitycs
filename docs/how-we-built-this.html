Components

The six pieces

Each component is independent and has a single responsibility.

Piece 01
☁️
Apify — The Data Fetcher
Meta's Ad Library is a React app — a normal HTTP request returns empty HTML. You need a real browser running JavaScript. Apify runs a headless Chrome in the cloud, handles IP rotation so Meta doesn't rate-limit you, and returns clean structured JSON.

We use apify/facebook-ads-scraper — Apify's own officially maintained actor. Their team fixes it when Meta changes the page structure. Not us.
apify/facebook-ads-scraper
Piece 02
🐍
Python Scripts
fetch_ads.py — reads YAML config, builds Ad Library URLs from page IDs, calls Apify, normalizes camelCase → snake_case, writes timestamped JSON.

update_sheet.py — append-only history: new ads get appended, existing ads get last_seen updated, retired ads get flagged. Writes latest_diff.json.

format_sheet.py — one batch of formatting requests: navy headers, alternating rows, green/red for active status. Idempotent.
3 scripts, 1 job each
Piece 03
🤖
Claude Code Integration
/scan is a custom slash command defined in .claude/commands/scan.md. It delegates all work to the meta-ads-analyst subagent — a separate Claude instance with its own tool calls and context.

The subagent reads latest_diff.json (compact summary) — not the raw 126-row JSON. This keeps the AI focused on what changed, not everything that exists.
.claude/agents/meta-ads-analyst.md
Piece 04
📊
Google Sheet — Append-Only History
One tab: raw_ads. Every row is one ad. The script never edits old rows — only appends new ones and updates last_seen.

This gives you a permanent record of every ad every competitor ever ran, when it started, and when it stopped. You can answer "how long did Biblusi run their summer promo last year?" — because that data is never deleted.
18 columns · append-only
Piece 05
🧠
Intelligence Report
The report is the product — everything else is infrastructure to produce it. It doesn't list all 126 ads. It identifies what changed, what's working, and what you should study.

"Palitra L's 57-day subscription explainer is almost certainly profitable" is an inference, not a raw data point. The sheet is for data. The report is for decisions.
reports/2026-05-14.md
Piece 06
🖥️
HTML Dashboard
Static HTML/CSS — no build step, no framework, no server required. Served via Python's built-in HTTP server on port 8080.

In GitHub Codespaces, make the port public and share the URL: https://{CODESPACE}-8080.app.github.dev/reports/dashboard.html

Key findings

What the first scan revealed about the Georgian publishing market.

📦
Biblusi launched Litbox
A subscription box (books + lifestyle items), 3 ads live, celebrity endorsement. Direct competitor to Palitra L's subscription funnel.
🏆
Palitra L's 57-day ad
Most durable ad in the set. Educational hook — "how to sign up" — rather than a discount. At 57 days, it's almost certainly profitable.
⚡
Intelekti's 5-hour flash sale
Every book for 15 GEL, 15:00–20:00 only. Time-gating mechanic that nobody else in the competitive set uses.
🌑
Artanuji is entirely dark
Zero active ads. All 7 "new" entries are historical 2021–2024 ads surfacing for the first time in the system.
🇬🇪
100% Georgian-language copy
Across all 6 competitors, every ad is in Georgian. No English. The market is entirely local-language.
🔍
Page IDs are permanent
Page names change. The numeric page ID (e.g. 204459169625213) never does. All tracking is ID-based, stored in config/advertisers.yaml.

Architecture

Key design decisions

The choices that shaped the system — and why.

✓
Page IDs over page URLs
IDs are permanent. URLs are not. A publisher can rename their Facebook page tomorrow. The numeric ID assigned when the page was created never changes.
✓
Append-only sheet
Never lose history. The whole value of the system is the longitudinal record. Overwriting rows means you can't answer "how long did they run that campaign last summer?"
✓
Diff JSON as analyst input
The subagent reads a compact summary — not 126 raw ad objects. This keeps the AI's context focused on what changed, not everything that exists. Smaller context = sharper analysis.
✓
Opinionated reports
The sheet shows data. The report makes arguments. "This ad is probably profitable" is more useful to a decision-maker than "this ad has run 57 days."
✓
Apify over DIY scraper
Outsource the part that breaks when Meta changes things. Own the part that interprets the data. Apify fixes the scraper — we just call their API.
Getting Started

Setup in 6 steps

From zero to running your first scan.

1
Install dependencies
pip install -r requirements.txt
2
Configure environment
cp .env.example .env # Fill in APIFY_TOKEN, GOOGLE_SHEET_ID, GOOGLE_SERVICE_ACCOUNT_JSON
3
Add competitors to config
Edit config/advertisers.yaml — each entry needs a slug, name, and page_url.
4
Resolve page IDs (one time only)
python scripts/fetch_ads.py --resolve-only # Copy the printed IDs into advertisers.yaml
5
Run first scan manually
python scripts/fetch_ads.py python scripts/update_sheet.py python scripts/format_sheet.py # optional formatting
6
From now on, just use /scan
/scan # all competitors /scan biblusi diogene # specific ones
Reference

Concepts glossary

Plain-language definitions for every technical term in this system.

Apify
A cloud platform for web scraping. You call their API, they run a headless browser in the cloud, you get back structured data.
Headless browser
A real web browser (Chrome) running without a visible window, controlled by code. Needed when a site requires JavaScript to render its content.
Actor
Apify's term for a scraper module. apify/facebook-ads-scraper is the actor we use.
Page ID
Meta's permanent numeric identifier for a Facebook page. Never changes even if the page renames itself.
Subagent
A separate Claude instance spawned to handle a specific task. Runs its own tool calls without cluttering the main conversation.
Diff
latest_diff.json — a structured summary of what changed between scans: new ads, retired ads, still-running ads, per advertiser.
Service account
A non-human Google account used for server-to-server API access. Lets Python scripts read/write the Google Sheet without a human login.
MCP
Model Context Protocol — a protocol that lets Claude connect to external tools and services like browsers, APIs, and databases.
Append-only
A write strategy where old rows are never edited or deleted. Every new piece of data becomes a new row. History is permanent.
